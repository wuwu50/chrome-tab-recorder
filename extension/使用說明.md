# 分頁影音錄影機

這是 Chrome 擴充功能初版，錄製一個指定分頁的網頁內容與播放聲音。不是獨立 EXE，也不包含網址列、工具列或整個 Chrome 視窗。

## 安裝

1. 需要 Chrome 116 或更新版本。
2. 在網址列輸入 `chrome://extensions`。
3. 開啟右上角「開發人員模式」。
4. 按「載入未封裝項目」，選擇這個包含 manifest.json 的資料夾。
5. 在工具列的拼圖選單中，釘選「分頁影音錄影機」。

## 錄影

### 獨立 UI 控制視窗

在要錄製的分頁點工具列圖示，按「開啟獨立控制視窗」，即可開啟完整介面，包含錄影狀態、計時、已寫入大小、目標分頁、畫質設定、開始／停止與重新儲存按鈕。此視窗是 Chrome 擴充功能視窗，不是獨立 EXE。

目標會固定為開啟控制視窗時的分頁，避免錄到控制介面本身。要換目標，請在另一個分頁重新點工具列圖示，再按「開啟獨立控制視窗」。錄影中更換選擇不會改變當次錄製目標。關閉控制視窗不會停止背景錄影；可再次開啟。

若已安裝舊版，替換檔案後到 `chrome://extensions` 按此擴充功能的重新載入按鈕。請先完成舊版錄影並儲存。

1. 開啟要錄製的分頁，先開始播放影片。
2. 點擴充功能圖示，選擇畫質，按「開始錄製目前分頁」。
3. 可以關閉操作面板、切換分頁、使用其他程式，或最小化 Chrome。
4. 要結束時，還原 Chrome，再點擴充功能圖示，按「停止並儲存」。從其他分頁開啟面板也能停止。
5. 在下載視窗選擇儲存位置。固定儲存真正的 MP4 影片。Chrome 沒有可用的 MP4 編碼器時會提示更新 Chrome，不會改成其他格式。
6. 若取消下載，可按「重新儲存影片」。儲存成功後才刪除暫存資料；下一次錄影前必須先儲存或刪除上一份暫存。

## 背景與最小化

### 1080p 與 120 FPS（v1.4.0）

画質選單新增「1080p · 120 FPS / 32 Mbps」（預設）與「1080p · 60 FPS / 16 Mbps」。固定請求 1920×1080 與所選幀率，並驗證 Chrome 回報的擷取設定。不能取得設定時會報錯並清理串流，請改選較低設定；不會默默降幀後仍標示 120 FPS。

控制面板顯示的是 Chrome 回報的擷取設定，不是實際編碼 FPS 的測量結果。網頁沒有持續更新、來源只有 30／60 FPS、GPU 編碼效能不足或 Chrome 最小化時，輸出仍可能有重複畫面或掉幀。1080p 尺寸也不會增加低解析度影片的細節。120 FPS 模式約需 14.5 GB／小時的影片空間，儲存期間需額外容納暫存，請先短錄測試。

錄影工作放在 Chrome 的隱藏背景頁面，最小化不會由本程式主動停止錄影。但 Chrome、顯示卡與網站本身可能降低更新頻率；網站也可能在切換分頁、失去焦點或最小化時暫停影片。無法保證所有網站最小化後仍有連續畫面。請先錄 30–60 秒測試你的目標網站。

Chrome 不可關閉，電腦不可休眠。關閉被錄製的分頁會結束錄製並嘗試儲存。切換其他分頁不會改變錄製目標，但在目標分頁內導覽會錄到新頁面。

## 音訊範圍

### 靜音錄影（v1.5.0）

預設不勾選「錄影時也播放聲音到喇叭」，因此錄影期間電腦不播放目標分頁聲音，影片仍錄入分頁音訊。若希望同時聽到聲音，可以在開始前勾選；原本已靜音的分頁仍維持安靜監聽模式。

如果 Chrome 分頁／網站已靜音，程式會先建立擷取串流，再暫時解除「錄製分頁」的靜音，透過不接喇叭的擷取方式錄音。停止或開始失敗時，會先恢復原先的靜音，再釋放串流。录影途中再用 Chrome 靜音會關閉喇叭監聽，繼續錄音，結束後恢復靜音。不會修改其他分頁或網站全域設定。

網頁播放器內部的靜音、音量設為 0 或停止播放，無法用這個方式恢復聲音；請讓播放器保持播放且音量大於 0。瀏覽器崩潰／擴充功能強制重載不會執行正常清理，請手動確認分頁靜音狀態。正式網站上的音訊行為仍需實測。

此方式依據 Chrome tabCapture 的本機音訊播放抑制機制：https://developer.chrome.com/docs/extensions/reference/api/tabCapture

- 音訊來源只使用指定分頁串流，不開啟麥克風、不擷取桌面音訊。
- 其他分頁、播放器、遊戲與系統通知的聲音不會被此錄影機混入。
- 同一分頁內所有播放聲音都會錄入，包含網頁廣告。
- 若網頁本身把麥克風聲音播放回分頁，該播放內容也屬於分頁音訊；本工具不會另行啟動麥克風。

## 程式內檢查更新（v1.2.0）

### 確認後直接安裝（v1.6.0）

Windows EXE 安裝版會註冊本機更新器。發現新版後按「確認更新並自動安裝」，Chrome 可能詢問是否開啟錄影機。原生視窗會再次檢查官方版本並詢問是否安裝；確認後自動下載到本機更新快取、驗證 SHA-256，沿用原來的安裝位置，不需要手動選擇檔案或資料夾。

也可直接從桌面或開始功能表開啟錄影機，按「檢查更新並安裝」。請先停止所有錄影並儲存；安裝後到 Chrome 擴充功能頁重新載入。ZIP 版沒有本機更新器，須先安裝 EXE。v1.5.0 與更早版本需要先手動安裝 v1.6.0 一次，之後才有此能力。

控制視窗右側的「程式更新」會顯示目前版本。預設使用本專案的 GitHub 版本來源：`https://raw.githubusercontent.com/wuwu50/chrome-tab-recorder/main/version.json`。第一次按「檢查更新」時 Chrome 可能詢問是否允許連線，允許後即可查詢。只有按下檢查時會連線，不定時背景輪詢，也不傳送錄影片段、目標網址或影片內容。

如需其他發布來源，展開「設定更新來源」，輸入版本 JSON 的 HTTPS 網址，再按「儲存來源」。

尚未提供發布來源時會明確顯示「尚未設定更新來源」，不會假裝已是最新版。清空網址並儲存可停止使用該更新來源。舊的網站存取權限可在 Chrome 擴充功能設定內移除。

發現新版時會顯示版本、更新說明與「下載新版」連結，這個連結保留手動下載方式。Windows EXE 安裝版另提供「確認更新並自動安裝」，會使用本程式官方 GitHub 更新器，與手動設定的其他發布来源無關。請完成錄影並儲存後更新，安裝後重新載入擴充功能。

### 日後發布版本

把 `version.example.json` 的 version、downloadUrl、notes 改為實際內容，發布到可直接讀取的 HTTPS 網址（例如 GitHub 的 raw JSON 網址）。downloadUrl 可指向 GitHub Releases ZIP。介面填的是 JSON 直接連結，不是 GitHub 網頁或 ZIP 連結。來源不可要求登入或重新導向；回應上限 64 KB，連線逾時 12 秒。

版本使用 1 至 4 段數字，例如 `1.2.0`、`1.10.0`。更新時同時調整 manifest.json 的 version，並上傳新版 ZIP 和版本 JSON。本專案的 GitHub Actions 會在 Release 成功後發布版本 JSON。

更新連線透過 Chrome 的可選網站權限，只在設定來源時請求該主機：https://developer.chrome.com/docs/extensions/reference/api/permissions

## 暫存空間與錄製限制

錄影約每 5 秒逐段提交到瀏覽器本機暫存，避免把整部影片放在記憶體。標準畫質影片約 1.9 GB／小時，高畫質約 3.7 GB／小時，實際取決於編碼器。儲存期間需同時容納暫存與輸出檔案。瀏覽器暫存配額或磁碟空間不足會停止錄製，嘗試儲存已寫入部分，損壞的部分不保證可播放。

v1.7.0 會保留已提交的錄影片段；錄影機意外停止後重新開啟控制視窗，可嘗試「重新儲存影片」。意外中斷的 MP4 尾段可能不完整，無法保證可播放。尚未提交的資料、舊版未完成的暫存、清除瀏覽器資料或移除擴充功能後的資料無法保證取回。更新前仍請先停止並完成儲存。

待寫入資料上限為 64 MB；超過上限會停止錄影並嘗試保留先前片段，避免待寫入資料無限堆積。會檢查 Chrome 估計的暫存配額，預留組合 MP4 的空間；不是精確的磁碟剩餘空間保證。組合影片時需要同時容納片段與 MP4，下載時還需要輸出檔空間。

1080p／120 FPS 的 32 Mbps 目標約產生 7.2 GB／半小時（未含音訊，實際依編碼器而異）。長時間錄製建議先測試 1080p／60 FPS；120 FPS 選項仍保留，不會自動改成 60 FPS。

按「匯出錯誤紀錄」下載 JSON；紀錄包含版本、時間、畫面設定、資料量及錯誤訊息，不包含網頁標題或網址，也不會自動上傳。每分鐘保留一筆進度與最近 40 筆事件；Chrome 程序突然消失時可能沒有最後一筆錯誤。

受保護的串流影片可能出現黑畫面；此工具不繞過網站的內容保護。Chrome 設定頁、Chrome Web Store 與部分特殊頁面不能擷取。

## 實際驗收

1. 分頁 A 播放影片，開始錄影。
2. 分頁 B 同時播放不同音樂，或讓其他程式播放音效。
3. 對麥克風說話，確認輸出沒有這些外部聲音。
4. 最小化 Chrome 至少 30 秒，再還原並停止。
5. 播放輸出檔案，確認 A 的影片持續更新、聲音正常，且没有 B 或麥克風的聲音。
6. 再錄一次，停止時取消下載，確認「重新儲存影片」能成功取回。

已進行程式語法與模擬生命週期測試；實際網站、最小化與音訊隔離仍需在你的 Chrome 實測，不能以模擬測試代替。

## v1.8.0 長錄自動分段

每次錄影仍使用指定分頁的同一個影音擷取串流，維持選定的畫質、FPS、音訊隔離與靜音處理。MP4 編碼器在每段約 1 GiB 或 5 分鐘時停止並重新建立，依資料事件抵達時間切換，實際段落可能略大或略長。這是為了避開 Chromium 155 的 MP4 OutputPositionTracker 使用 uint32_t 累計位置、超過 4 GiB 時觸發 CHECK 的限制：
https://github.com/chromium/chromium/blob/155.0.8059.39/media/muxers/output_position_tracker.cc

同一次長錄產生多個獨立 MP4，例如「分頁錄影-時間-第001段.mp4」「第002段.mp4」。不直接串接獨立 MP4，也不自動合併。切換編碼器、完成前段暫存與啟動下一段之間可能有短暫影音缺口，無法保證無縫錄製。若需要單一影片，需後續用影片工具合併。

停止後依序下載各段。多段會使用 Chrome 預設下載位置；Chrome 的下載位置／詢問設定或下載限制仍可能要求操作。單段仍會詢問儲存位置。取消或失敗時保留尚未儲存片段，重新開啟可繼續；只有所有段落下載完成或明確刪除時才清除暫存。v1.7.0 的舊暫存仍支援嘗試儲存，但不保證中斷的尾段可播放。

每段組合時需要該段 MP4 的額外暫存空間；未下載的所有原始片段會保留到全部下載完成。120 FPS 仍是擷取／編碼目標，不保證硬體與來源每秒都產生 120 個不同畫面。

本次驗證包含門檻切換、最後資料寫入、同一擷取串流、下載取消與重開續存、快速下載完成競態，以及實際 Chrome 以縮短切換門檻錄製多段可播放的 1080p MP4。短測試不代表已驗證使用者網站長錄或無縫切換。

## v1.9.0 更新並自動安裝

Windows EXE 安裝版使用官方更新來源時，主按鈕「更新並自動安裝」直接開啟已安裝的更新器。更新器檢查版本，確認後自行下載安裝包、驗證 SHA-256 並以無安裝位置選擇頁的更新流程安裝到原本目錄。不經 Chrome 的下載另存新檔，也不需要自行找 EXE。

更新專用視窗不再顯示第一次啟用 Chrome 擴充功能的資料夾操作。Chrome 若詢問是否開啟更新器，請允許。安裝完成後，在原有擴充功能卡片按「重新載入」即可，不要再次按「載入未封裝項目」。首次啟用仍須完成 Chrome 的資料夾選擇。

手動下載移到「設定更新來源／手動下載」內。自訂來源仍只做版本檢查與手動下載；原生自動更新器只安裝本專案官方 GitHub 安裝包。ZIP 版未安裝 Windows 更新器，需先安裝 EXE。

舊版目前可直接從桌面／開始功能表的錄影機按「檢查更新並安裝」升級，不需要在 Chrome 按「下載新版」。更新前先停止錄影並儲存所有暫存。


## 指定資料夾自動存 MP4（v1.10.0）

在錄影控制視窗的「儲存資料夾」按「選擇／更換資料夾」，選取實際要存放影片的資料夾並允許存取。設定會記住，下次錄影不需重新選擇。停止後所有段落會依序直接寫入該資料夾，檔名固定為 .mp4。

Chrome 僅提供資料夾名稱，完整位置請從資料夾選擇視窗確認。重新啟動或權限失效時，按「允許存取」；若資料夾不存在、磁碟滿或權限不足，暫存不會刪除，可重新授權／更換資料夾後按「重新儲存影片」。同名影片自動加上編號。未設定資料夾時仍使用原本 Chrome 下載方式。
